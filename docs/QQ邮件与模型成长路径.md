# QQ 邮件任务与模型成长路径

## 邮件任务流程

教师端“任务与推送”现在改为邮件流程：

1. 在“邮件收件设置”中登记一个演示学生邮箱，并记录该学生是否明确同意接收课程邮件。
2. 创建课前、课中或课后任务，设置章节、开放时间和截止时间；“通过 QQ 邮件发送”默认关闭，教师逐项开启。
3. 邮件可包含任务说明、章节提示、开放资料名称，以及最多 5 组与该章节引用资料相关的问答（学生问题、初步解释、学习提示和资料出处）。教师可先预览，再选择立即发送；勾选定时发送后，后台每分钟检查到期任务。
4. 发件箱记录待发、发送成功、暂缓或失败状态。SMTP未配置或未取得收件授权时不会发信；一次 SMTP 失败不会自动重试，避免重复发送。

当前原型只有一个虚构演示学生，邮件地址由教师在演示后台登记。生产版应由学生本人验证邮箱并授权，建立真实班级名单与权限；不能把演示身份切换当作正式认证。

## QQ 邮箱准备

1. 登录 QQ 邮箱，进入设置中的账号安全/第三方服务，开启 SMTP，并生成第三方客户端授权码。QQ 邮箱官方说明授权码是第三方客户端专用凭证，不能用 QQ 登录密码替代：[QQ 邮箱授权码帮助](https://help.mail.qq.com/detail/106/985)。
2. QQ 邮箱发件服务器使用 `smtp.qq.com`。本项目默认采用 SSL/TLS 465 端口；发件地址与 SMTP 用户名须为同一个完整邮箱地址。腾讯云配置文档也列出 QQ 邮箱 SMTP 服务器及 SSL 465 端口：[腾讯云邮件配置参数](https://intl.cloud.tencent.com/document/product/1266/71700)。
3. 在项目目录执行 `npm install` 安装 Nodemailer。之后把邮箱地址和授权码放入本机 `.env.local`：

```dotenv
QQ_MAIL_USER=完整的QQ邮箱地址
QQ_MAIL_APP_PASSWORD=邮箱生成的授权码
QQ_MAIL_HOST=smtp.qq.com
QQ_MAIL_PORT=465
PUBLIC_BASE_URL=https://学生可访问的课程域名
```

授权码不要发在聊天、邮件或前端代码中。`PUBLIC_BASE_URL` 只有部署好学生可访问的网站后再填写；本地 `localhost` 地址不能作为学生邮件里的课程入口。

当前项目服务只监听本机，不能让学生从别的设备访问。要实际向班级长期发邮件，需要部署持续运行的服务和持久化数据库，并配置公网/校内课程地址、真实身份、学生邮箱验证、退出授权、发信频率限制和邮件留存策略。邮件中当前内嵌任务与对话文字，不附加大型视频/文档；资料名和引用出处随邮件展示，打开课程资料需使用部署后的课程入口。

## “越用越聪明”分成三层

### 第一层：更新课程知识（当前已做）

学生问题与课程资料做本地检索；系统保留回答引用，教师修订后的内容先进入待审核，再发布到课程资料库。它提高的是课程内容覆盖和答疑可追溯性，不会改变大模型参数。

### 第二层：改进教学策略（当前有记录，后续补分析）

把重复卡点、学生反馈、错题解释、任务反思按章节汇总。教师据此补充示例、调整课前任务或重写提示。反馈只表示学习者体验，不等同于知识正确性；需要教师判断后才更新资料或教学活动。

### 第三层：训练模型参数（未来可选）

若确实需要模型本身适应本课程，先由教师把经核对的答疑整理成训练样例：问题、学生可能的初步解释、课程证据、期望的分步引导、必须避免的直接代答情形和引用要求。对原始互动去标识化、核对授权和使用目的，再按主题划分训练集与独立评估集。

新模型要先与当前模型做离线对照，检查课程事实和引用准确性、无依据时能否承认不足、是否保留学生的思考步骤。教师审核的回归题集未通过时，不发布新模型；发布后保留旧版本，便于回退。不要将“学生点了有帮助”直接当作正确训练答案，也不要把未审核聊天自动投入微调。

当前使用的 DeepSeek 是通过服务接口调用，本工程没有训练它的模型参数，也不假设该接口提供课程微调能力。真要训练，可在学校批准的环境中使用允许训练的模型或托管训练服务；平台、模型和数据方案届时另行评估。
