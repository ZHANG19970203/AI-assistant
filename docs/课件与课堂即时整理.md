# 课件、视频与课堂音频：及时整理方案与当前实现

更新：2026-10-28，Asia/Shanghai。

产品目标是课堂结束后尽快让学生拿到可用的复习支持。关键是在课前解析课件、课中持续处理语音和已讲内容，下课后只收尾、汇总和审核。不能把本地原型的结构整理速度当作真实语音识别或大模型响应速度。

## 当前能实际运行的范围

| 输入或环节 | 当前实现 | 尚需接入或验证 |
| --- | --- | --- |
| PPTX | 自动按真实幻灯片顺序提取文字、表格文字、备注；保留页码与原文 | 图片、公式、复杂图形、动画需OCR/多模态或人工说明；不判断解剖图是否正确 |
| 旧版PPT | 提示用户先另存为PPTX | 未执行Office自动转换 |
| 视频/音频文件 | 本地接收和保存，明确显示等待转写 | 音轨抽取、ASR和画面/动作分析均未接入；保存成功不代表解析成功 |
| SRT/VTT | 解析字幕时间戳和正文；可定位到对应时段 | 字幕是否与该视频匹配、是否准确须教师核对 |
| TXT/教师讲稿 | 接收正文并明确标记教师导入，未给出的时间显示未标注 | 不冒充自动音频转写 |
| 课堂收音 | 教师确认录音告知与授权后主动打开麦克风；浏览器约10秒输出一段；逐段上传确认、去重，可暂停/继续 | 未在本次实际开启用户麦克风；真实收音、回放、弱网和长课时须设备实测；流式ASR未接入 |
| 下课整理 | 点击“结束本节”前核对片段数量完整；有文字就自动生成原文摘要、结构导图和开放式提问草稿；无文字则等待转写 | 目前是抽取与规则组织，不是大模型语义总结；不生成未经核验的正确答案 |
| 教师发布 | 核对当前草稿版本与覆盖范围后发布；学生只能看到已发布材料；新增文字后自动更新待审核草稿并撤下旧发布状态 | 没有微信外发或正式班级认证；发布的课堂材料尚未自动加入答疑索引 |

课件上传单文件上限128MB；PPTX最多400页、解压规模160MB，单XML5MB；不运行宏、不访问外部关系、不执行Office。录音每片4MB、本节累计256MB；原始文件写入私有运行目录，不作为静态网站文件提供。当前结构导图最多覆盖160段已解析文字、摘要选前8段、开放题最多5题；界面明确显示覆盖段数。这是验证工作流程的限制，不应宣称完整理解了长课全部内容。

PPTX解析另需 Python 3 标准库。本机优先使用Codex捆绑Python；其他电脑安装Python 3，或通过 `PYTHON_BIN` 指定绝对路径。其余网页功能仍只需Node 24，无新增npm依赖。录音需支持MediaRecorder的浏览器及HTTPS/localhost；只有本人主动同意浏览器麦克风权限后才可开始。[MDN麦克风权限与安全上下文](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

## 希望学生感受到的课堂节奏

1. **课前**：教师上传本节PPT；先形成资料目录、术语表和页码索引。图像类内容进入待核对列表，不能当作已识别事实。
2. **课中**：教师主动开采集，ASR持续返回中间文字和句子最终文字。学生不需要一直盯着屏幕；学伴安静整理，按教师开放的任务提供支持。
3. **每个小节后**：只用已完成识别的句子更新章节草稿，保留时间戳和对应幻灯片。不把未稳定的中间文字作为可靠知识。
4. **老师讲完**：教师点“结束本节”，等待最后一段确认保存、最后一句完成识别，再并行生成摘要、导图与练习草稿。
5. **教师快速审核**：核对术语、解剖关系、问题及覆盖范围，修改或撤回不当内容；经确认后学生在“课堂回顾”看到材料。

拟定性能目标：课堂已讲内容持续更新，最终语音结束后数秒完成转写收尾；下课后1分钟内先出摘要，1–3分钟内出可审核的导图与3–5道练习草稿。**这些是待服务选型、网络、课时和设备实测的目标，不是当前已达到的承诺。** 教师审核时间另计；识别失败、低置信术语或网络中断时显示真实等待状态和已覆盖范围。

## 真实流式语音与视频链路

```text
教师电脑/教室麦克风（明确开启、可暂停）
 → 音频采集、时间戳、片段缓存和上传确认
 → 转为供应商支持的单声道格式/采样率
 → 服务端实时ASR（中间文字 → 句子最终文字）
 → 最终句事件入库、去重与版本管理
 → 已讲章节增量整理、对应PPT页和术语
 → 结束信号：等待最后片段与TranscriptionCompleted
 → 摘要 / 导图 / 形成性练习并行草拟
 → 引文与覆盖范围校验 → 教师审核 → 学生材料
```

真实视频还要拆成两路：音轨转写与抽帧/OCR/图像理解。课程里的人体运动动作、触诊位置及解剖图，不能只凭字幕判定正确；先做“可定位的内容索引”，再由教师审核图像解释。已存在字幕时先用字幕加速，但要核对时间偏移和术语。

已实际读取的阿里云官方协议支持持续发送音频并接收中间/句末结果，结束时发送StopTranscription并等待TranscriptionCompleted。该接口需要项目与鉴权，且有明确音频格式和采样率要求。本工程没有选定供应商、调用账号或使用凭证。[官方实时语音WebSocket说明](https://help.aliyun.com/zh/isi/user-guide/websocket)

浏览器录制的WebM片段不应被当作各自独立可识别的完整文件。当前只按序保存，后续必须按连续流重组或使用AudioWorklet/服务端转码输出ASR要求的格式；不把WebM字节直接当PCM发送。MediaRecorder的timeslice并非精确时钟，必须使用实际采集时间和服务端确认时间，而非片段数乘10秒计算时长。[MDN分段数据事件](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)

## 需要的生产适配器

- ASR：流式会话建立、续期、句子最终事件、断线恢复、术语热词、结束确认；中间识别结果与最终文字分开保存。
- 媒体处理：FFmpeg等受控进程抽音轨/转码；限制格式、时长和资源；视频抽帧与OCR另排队。本机当前未发现可用的FFmpeg。
- 内容生成：选定机构允许的模型，输入当前课程、PPT页、最终转写和目标；返回结构化摘要、导图节点/边、题目、参考答案、依据和不确定项。服务端拒绝没有来源的节点/答案。
- 调度：持久化作业、重试与取消；进程重启不丢任务。不能让网页关闭导致正式ASR或生成任务中断。
- 推送：教师发布后生成站内材料；有真实订阅权限时才通知学生。课堂音频默认不向学生公开。

教师说“本题答案是……”不应被自动收进学生公开问答库。每次课堂内容发布必须核对是否混入受限测评、学生姓名或其他私有讨论；原始音频、教师材料与学生回顾材料分层授权。录音不自动用于情绪识别、考勤或学生能力评价。

## 本次验证

- 对一份已有约71.2MB的真实PPTX做只读解析，读出37页，其中36页含可提取文字；该样本没有备注文字。读取XML与组织结果在本机约90毫秒，此数字不含网络上传、OCR、语义生成或人工审核，也不代表所有课件性能。
- 用原创最小PPTX验证了幻灯片关系顺序、备注与页码；用SRT验证了毫秒时间戳；用合成字节验证了片段去重、缺片拒绝结束和无文字不生成内容。
- 浏览器走通建立课堂、查看PPT解析结果、导入明确标记的演示讲稿、结束后自动整理、教师确认发布。没有采集实际教室声音或用户麦克风，没有把手动讲稿标成ASR结果。
- 小程序尚未增加本次录音/整理界面；当前采集入口为教师网页，学生网页可查看审核发布材料。
