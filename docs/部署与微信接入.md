# 部署与微信接入操作说明

核查日期：2026-11-03（Asia/Shanghai）。当前交付仍是本地工程；微信主体、真实登录、开发者工具和真机联调、公网发布均未配置。已新增可选 SiliconFlow DeepSeek 问答适配；服务端密钥存于本机被忽略的 `.env.local`，已用虚构演示内容完成一次真实模型请求；没有上传真实课程/学生资料。

## 1. 本地启动与验证

需要 Node.js 24.19 或同系列支持 `node:sqlite` 的运行时。项目无外部 npm 依赖；可离线运行，也可选用本机 `.env.local` 配置 SiliconFlow DeepSeek。从项目目录运行：

```powershell
node --test
node server.mjs
```

默认地址为 `http://127.0.0.1:4317`，只供本机。演示数据由 SQLite 本地持久保存，开发者应将运行数据和 `.env.local` 排除在源码提交与交付压缩包之外。网页角色切换及 `x-demo-role` 用于展示流程，不具有生产认证能力。当前不得把该服务器直接转发到公网，也不要放入真实学生资料。

推荐演练顺序：学生提问并查看引文→完成任务及写反思→关闭/开启本地提醒→教师新增纯文本资料并审核→学生再检索→教师创建到期任务→运行本地调度→检查发件箱去重。当前提醒只产生本地模拟记录；“已模拟”不得解释为微信已送达。

## 2. 小程序骨架的使用

1. 打开微信开发者工具，导入项目下 `miniprogram/`，可先用游客模式。`touristappid` 只是开发占位，不能发布、登录真实学生或获取真实模板能力。
2. `miniprogram/config.js` 默认 `transportMode: 'offline-demo'`，页面使用原创演示资料，不发网络请求；任务与偏好只保存在小程序进程内，重启后重置，与网页 SQLite 数据独立。
3. 骨架提供课程任务、资料提问、自我解释、分级演示练习、学生主动表达卡点、笔记、六维待证据页和提醒偏好。练习正确率独立显示，六维全部初始 `null`，没有教师评分或能力诊断。已保留 `local-api` 接口适配器，地址为 `http://127.0.0.1:4317`；但后端来源保护目前不接受微信 Referer，且未接入正式身份，因此这条路径尚未联通，不能用关闭后端保护来绕过。新增学生页面仅在默认离线模式提供，正式服务契约仍待联调。
4. 本机回环地址不能直接用于手机真机。真机/体验版必须换成获准的测试 HTTPS 服务，并使用正式身份会话，不能继续传演示角色头。
5. `enableWechatSubscription` 默认 `false`，模板列表为空。按钮只解释当前状态。即使配置后获得客户端 `accept`，骨架也不会把它写成服务端已核验额度；生产订阅回传、平台事件与发送适配器需另外实现。

## 3. 账号与身份接入

由用户/机构管理员完成小程序主体注册、身份认证和适用类目确认，添加开发者/体验者。具体所需材料、资费和能力以公众平台所见为准，本工程没有查验账号条件。

正式流程：小程序 `wx.login()` 获取一次性 code→后端调用 `code2Session`→服务端建立自己的短期会话→用邀请码/校内流程绑定课程成员。openid 用作微信侧映射，不能接受客户端任意声称的 openid；教师角色必须由机构/管理员分配。`session_key`、AppSecret 不下发客户端，也不写入前端代码、日志或仓库。该流程来自微信[登录指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)及[登录凭证校验](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)。

生产需要补充的 API（当前未实现）：`POST /auth/wechat`、退出/刷新会话、课程绑定、教师机构认证、微信事件验签与去重。后台统一用服务端会话确定用户与课程权限，不保留演示角色头的授权方式。

## 4. HTTPS、域名与云部署

微信常规网络请求要求配置服务器域名，并使用相应 HTTPS/WSS；域名不能是 localhost 或普通公网 IP，官方网络说明要求备案。开发工具跳过校验只适用于调试。`api.weixin.qq.com` 不能配置为小程序服务器域名，平台接口在后台调用。[微信网络能力说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

两种部署方式择一：

| 方式 | 工作 | 适用条件 |
| --- | --- | --- |
| 机构允许的云服务器/容器平台 | API 容器、PostgreSQL、对象存储、HTTPS 反向代理和任务 worker；后台配置合法域名 | 已有运维、域名与数据库能力 |
| 微信云托管/云开发 | 评估其登录、云调用、网络和定时能力，迁移数据库/存储适配器 | 主体拥有相应能力、费用与数据区域满足机构要求 |

不直接将本地 SQLite/demo 服务复制为生产。先实现认证/课程隔离、PostgreSQL迁移、凭证管理、备份恢复、监控限流和审计，再建测试环境。API/worker 和数据库分离；对象存储原件保持私有，按授权签发短期访问链接。生产对文件做大小/类型检查和解析隔离。

## 5. 订阅提醒不是无限主动推送

学生在任务页主动点击后，才发起 `wx.requestSubscribeMessage`。按模板返回值区分 accept/reject/ban/filter，拒绝不影响课程使用。一次性订阅的可用发送次数会被消耗，不能把“一次同意”当作整学期都能推送；长期订阅是否可用需在真实主体与类目下确认。[订阅接口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)、[发送接口与错误码 43101](https://developers.weixin.qq.com/miniprogram/dev/server/API/mp-message-management/subscribe-message/api_sendmessage.html)

客户端回传是用户操作证据之一；后端还要接收并核验平台的订阅/变更/发送结果事件，统一维护授权和发送账本。学生撤回或关闭本系统提醒后，取消未发消息；在发送前再次检查，不能只在创建任务时判断。平台明确提供拒收变更和发送结果事件。[订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)

建议流程（以下为本项目工程设计）：

```text
教师保存任务 + 同事务创建 outbox（唯一键 task/student/template/scheduleVersion）
  → 定时 worker 领取并加租约
  → 检查任务仍有效/未完成、学生偏好、安静时段、模板有效、一次性次数
  → 预留次数 + 记录 attempt
  → 服务端发送
  → 记录 API 结果与平台事件；成功则核销，确定失败则按类型释放或结束
```

不要宣称外部发送“精确一次”。数据库可去重任务，但网络超时可能发生“平台已接收而本系统未知”；此时标记 `unknown`，等待可核验结果或人工处理，不无条件重发。可重试的临时失败采用指数退避与次数上限；拒订阅/额度耗尽/无效模板停止重试并保留站内待办。静默时段内延期，过期或已完成任务不补发，频次上限由教师和学生偏好共同限制。worker 与网页打开无关，必须由常驻任务或平台定时触发运行。当前本地服务器每 60 秒检查一次模拟任务，也支持教师手动检查；这不是生产独立 worker，本机进程停止后不会运行。

微信后台 access_token 只在服务端缓存，并按响应过期时间统一刷新；避免各进程反复获取相互覆盖。官方也提供稳定版凭据或部分云调用方式。AppSecret 使用服务端密钥管理，生产日志应屏蔽带 token/secret 的请求信息。[获取接口调用凭据](https://developers.weixin.qq.com/miniprogram/dev/server/API/mp-access-token/api_getaccesstoken.html)

## 6. 生产部署执行清单

| 顺序 | 操作 | 验证证据 |
| --- | --- | --- |
| 1 | 用户确定主体、服务区域、预算、课程和隐私负责人 | 账号角色、课程材料清单、机构批准记录 |
| 2 | 创建测试基础设施，安装正式数据库，审核迁移 | 数据库迁移记录、最小权限、恢复备份实测 |
| 3 | 注入服务端密钥；后端实现微信登录和教师认证 | 密钥扫描通过、会话过期/越权用例通过 |
| 4 | 建立 HTTPS 测试域名或云托管调用；后台配置 | 关闭“跳过校验”后的模拟器和真机成功 |
| 5 | 接入获准模型、解析与检索；教师核验首章 | 模型评测、页码抽查、拒答/泄题测试记录 |
| 6 | 配置真实模板、事件回调和独立 worker | 真实授权、撤回、额度不足、重复与未知结果测试 |
| 7 | 试点隐私说明、删除/导出与告警；体验版验证 | 教师和自愿学生验收，运行/费用可观测 |
| 8 | 用户明确批准上线后提交平台审核/发布 | 平台状态、真实发布版本及可访问证据 |

当前只完成本地工程阶段。未取得用户对任何实际外部发布的最终确认，也没有把以上任一项标记为已上线。

## 7. 配置与密钥边界

| 配置 | 可提交源码？ | 当前状态 |
| --- | --- | --- |
| AppID、公开模板ID、API域名 | 通常不是秘密，但须有真实账号 | 未配置，使用游客占位 |
| AppSecret、模型 API key、数据库密码、会话签名密钥 | 否，服务端密钥管理 | SiliconFlow key 仅在本机 `.env.local`；微信密钥及生产数据库凭证未配置 |
| webhook Token/AES key | 否，服务端保存 | 未配置；事件签名验证未实现 |
| 学生名单、openid、学习记录、课程原件 | 不作为公开源码或压缩包内容 | 仅使用演示数据，资料复用待审核 |

供应商的账户、计费、地域、存储与训练用途条款须在开通时再次核查。当前接入的 SiliconFlow 适配只对已审核课程摘录调用聊天补全接口；未接向量嵌入，也未用于课堂录音转写。学生输入会传给供应商，因此真实学生资料启用前须由学校确认数据处理条件。参见[模型接入说明](硅基流动DeepSeek接入说明.md)。
